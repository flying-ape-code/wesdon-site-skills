# 既有官网发布

先保护客户数据，再更新代码。每个客户独立构建和发布，禁止将某客户配置、数据库、上传目录或管理员复制到另一客户。

## 发布前

1. 获得发布负责人对目标站点、变更范围和发布时间的明确授权。
2. 读取台账确认站点标识、环境、域名、当前风险与待办；不要从台账读取凭据。
3. 只读检查容器健康、`/api/health`、可用备份和实例目录。
4. 对模板/共享代码升级，先选择一个非关键或已授权的灰度站点；配置与内容变更只作用于目标实例。

## 执行

1. 先创建并核验目标站点备份。
2. 使用现有更新脚本或实例 compose 文件构建并重启目标站点；不得更新所有实例后才验收。
3. 运行迁移时核对目标数据库名称；禁止运行历史内容导入。
4. 验证容器健康、内部健康接口、反向代理域名、后台登录和核心页面。
5. 失败时停止扩散，记录错误并按已验证备份执行恢复；不要盲目重试。
6. 灰度通过后，逐站分批发布，每站独立验收。

## 台账记录

向“发布与变更”新增一条记录：变更事项、站点标识、时间、操作类型、结果、验收摘要、备份/回滚点、负责人、授权或工单。同步更新“站点总览”的最后同步时间和待办。

## 禁止项

不要在发布中创建文章；不要打印凭据；不要手改 1Panel 托管的 OpenResty 配置；不要因一次更新而共享或重建其他客户数据库。
